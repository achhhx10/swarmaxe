# Agents and the `/swarm` command

`/swarm` is a **command** (a prompt), not an agent. It runs in whatever primary
agent you have selected, decomposes the task, and then spawns workers.

That only works because three agents exist:

| Agent | Role | Policy |
|---|---|---|
| `swarm-worker` | Executes one subtask in an isolated session | full tools |
| `swarm-planner` | Strategic decomposition, read-only, **machine JSON output** | edit/shell/subagent denied — it cannot spawn, so extra work becomes an extra subtask |
| `swarm-researcher` | Fetches docs in disposable context, stores findings | read-only |
| `swarm-analyst` | Explains how a project works, `path:line` citations | read-only |

## Two entry points

| Command | Purpose | Workers |
|---|---|---|
| `/swarm` | implement: cells, reservations, review, verification | `swarm-worker` (writes) |
| `/analyse` | understand: read-only report, no cells, no writes | `swarm-analyst` (denied edit/shell) |

`/analyse` is safe to run from **Plan mode**: nothing it spawns can modify the
tree, and its only permitted write is an optional report under `~/.opencode/plan/`.

## Why they are not inlined into `/swarm`

`swarm_spawn_subtask` only *builds* a prompt. The actual worker is created by:

```ts
subagent(agent="swarm-worker", prompt="<prompt from swarm_spawn_subtask>")
```

Separate sessions give you: fresh context (the coordinator's context is the
scarce resource), a per-subtask model (`worker_model`), read-only policies for
planner/researcher, parallelism, file reservations, checkpoints and the review
loop. Inlining all of that into the coordinator would exhaust its context and
drop the permission boundaries.

## `mode: subagent`

All three ship with `mode: subagent`: **`/swarm` is the only entry point.** They
do not appear in the agent picker, because selecting one by hand is a mistake —
a worker without a cell, a reservation or a review has no coordinator to report
to, and the planner's answer is raw JSON meant for
`swarm_validate_decomposition`, not for a human to read.

`subagent(agent="swarm-worker", …)` still resolves them by name.

If you ever need to debug one directly, temporarily set `mode: all`, or invoke
it through `/swarm` with a single-subtask scope.

## Where they live

```
~/.config/opencode/agents/swarm-worker.md
~/.config/opencode/agents/swarm-planner.md
~/.config/opencode/agents/swarm-researcher.md
~/.config/opencode/commands/swarm.md
```

Check their state at any time:

```bash
~/.config/opencode/patches/swarmaxe-agents.sh
```

They are generated by `swarm setup` and shipped here so a fresh machine
can run `/swarm` immediately. `install.sh` keeps a `*.pre-swarmaxe` copy of any
file it replaces, and `uninstall.sh` restores it.
